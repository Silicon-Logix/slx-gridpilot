# Operator interface

GridPilot 0.4.2 uses the Silicon LogiX visual language: light workspace, navy viewport, purple primary actions, product header, dedicated workflows, consistent cards and a product About. Presentation uses Slint; the desktop does not depend on Qt. Inter is embedded in the executable under the SIL Open Font License; no runtime font download is needed. Buttons reserve space for their measured caption and use concise labels. Hover / selection transitions and gauge interpolation are presentation effects; numeric values remain confirmed telemetry.

The original GLB pack remains unchanged. Two application presentation overrides hide Service_Road and lift the complete ElectricalYard_ROOT assembly by 0.18 m to remove coplanar pad / grass flicker while preserving cable and support alignment. `assets/brand/logo-on-light.svg` adapts the original vector lettering to the light product header.

OPC UA Studio is the initial workspace, with actual endpoint, monitored-item and notification counters and an explicit command/feedback map. Real OPC UA/FORTE processes and simulated equipment are labelled separately. Its five-step learning tour advances only after observed Browse / Read results, matching controller acceptance, stable generation, safe rest, uncertain sensor quality and acknowledged recovery. Existing workspaces open Studio once after this update, then resume the saved page. OPC UA tools includes contextual explanations beside the live browser. Read [Explore OPC UA](opcua-learning.md).

Plant studio places the operator console at left, the twin and a 120-second signed-power trend in the centre, and unit cards / component inspector at right. The console scrolls at compact window sizes. Plant requests select automatic dispatch; individual unit requests enter manual dispatch. Enter a finite numeric MW value and explicitly apply it. Decimal comma is accepted in this field. Limits are ±5 MW plant / ±2.5 MW per unit. The hydraulic operating point may provide less power than requested.

U1 uses teal and U2 amber in cards, scene identifiers and selected materials. Select U1 / U2 in the console or click a scene identifier to inspect that unit without issuing a process command. Locate opens the cutaway when needed, restores live pivots and smoothly frames the selected unit. Overview / Cutaway restore the complete view. Unit detail uses the same inspection geometry for either unit and binds its pivots to the selected unit's actual telemetry; the identifier makes this distinction explicit. Picking ignores hidden road geometry. Card / marker selection and process commands remain independent.

Command progress uses the actual OPC UA receipt ID and matching controller LastCommand. Delivered is a device queue receipt; rejected is a matching controller rejection; executing means accepted without the expected confirmed outcome. Reached requires actual telemetry. Stop and zero-power requests require rotor / valve / wicket rest, not merely zero electrical power. Paused, interlocked, limited and unconfirmed states explain why completion cannot be asserted. An external command can supersede the latest acknowledgement; inspect the journal in that case. This is operator feedback, not an additional control/protection layer.

Process controls are disabled when plant services telemetry is unavailable, during read-only replay, during the comparison campaign, or while an acknowledgement is pending. Pause / speed and reset remain available where permitted by the runtime. Recovery travels through plant services so that a disconnected group endpoint can be restored. FORTE remains responsible for sequences, direction changes and fault release.

The OPC UA network page browses Objects/Device through native UA Browse and reads values with their actual statuses and source timestamps. Engineering units come from EUInformation properties. The selected device refreshes every 600 ms while this page is open; subscriptions remain independent. Reads of separate leaves are not a coherent transaction: use Snapshot for that. On failure, the page identifies retained values as stale. Component selection links to the corresponding unit or plant-services browser. The typed terminal also accepts read, concise commands and JSON Request input.

Search filters name, NodeId, type, value and unit without case sensitivity. Quality issues retains uncertain / bad leaf statuses and cached values from unavailable devices. Select a row for the detail panel, hexadecimal status, source UTC, namespace URI and native clipboard actions. Copy connection supplies the selected endpoint's external-client recipe, including namespace discovery and Request acknowledgement semantics. Export nodes writes nodes.json, nodes.csv and connection.txt in workspace/reports. String values in this browser and its exports are previews limited to 160 bytes; Read in the method terminal uses the coherent subscription snapshot.

Watchlist stores up to eight variable identifiers per device in workspace/opcua/watchlist.json. Namespace URI and string identifiers are saved instead of a numeric namespace index. Power and State are initial defaults. Select variables to pin; methods and objects cannot be pinned. Dedicated monitored items feed a 60-second numeric sparkline with auto scale on every page; strings show their value and quality. Uncertain/stale values break the numeric line and retained values are labelled. Continuous numeric history is available separately in Workbench.

Alarm acknowledgement appends an ACK event with the active alarm masks. It does not remove the injected cause or clear a controller latch. Clear cause & recover is a separate command. Guided scenario phases and metrics remain visible; physical values and replay history are preserved.

Session exports create local folders under workspace/reports with report.json, summary.txt, events.csv and trend.csv. The report includes confirmed state, model configuration, endpoint age / errors, version, model limits and metrics. Trend export includes the available 120-second GUI history, not a complete historian. Replay seeks/resets clear that history. Event CSV includes the available bounded runtime journal. Diagnostic bundles additionally include the last 128 KiB of each recognised application log and cached UA browser values. They are folders rather than ZIP archives and contain local diagnostic data. No export is sent externally or included in publication packages.

The product About presents identity, author, core ABI, runtime stack, evaluation terms, model limits, third-party notices, Slint attribution and website/contact actions. License and notice documents open in the application's scrollable reader, independent of Windows file associations. Contact actions open the browser; they do not submit project data.

## Workbench

Sequence diagnostics explain U1/U2 phases using confirmed inlet, distributor, rotor, communication, reservoir and fault feedback. A diagnostic condition describes feedback; FORTE remains responsible for transitions and permissives.

Trends & history offers twelve selectable numeric channels, independent scales and a movable 120-second window. The live view retains the latest 30 simulated minutes received by the supervisor. Continuous runtime history stores fixed-step numeric samples, changed commands and new journal events under `workspace/history`, including while another page is open. Select a file and session to inspect older data. CSV export includes the loaded history; archived files contain complete captured samples, while the live view follows received OPC UA snapshots. Files rotate at 50 MiB; capture pauses at a 500 MiB storage limit and reports a warning. Existing history is retained.

Test plans contain a name, 1–600 second duration, up to 64 timed commands and up to 64 feedback checks. Add/edit/remove rows, choose the target, action/field, expected value and tolerance, then save or load a local plan. Run validates the complete plan before resetting the session. Commands execute through the existing controller path; checks evaluate actual feedback on the first fixed tick at or after the requested time. Results identify accepted/rejected commands and each observed passed/failed assertion. Completion writes `workspace/reports/test-plan-<session>.json`. Cancel requests a controlled stop; reset also cancels the plan.

Replay lists full state recordings. Select a file, enter a simulation time and use Seek & pause. Seeking clamps to the recording range. Resume continues recorded playback; reset returns to live operation.

Preferences persist the page, camera, channel selections, panel widths, flow overlay and monitoring settings in `workspace/preferences.json`. Save & apply configures a separate watchlist subscription on each endpoint: 50–5000 ms sampling/publishing and optional absolute deadband in engineering units. The control Snapshot retains its separate 100 ms subscription. The OPC UA Watchlist reports server-revised intervals and connection count; selections remain monitored on every page.

Shortcuts: F1 About, Escape close overlays, F5 refresh OPC UA, Ctrl+1/Ctrl+2 locate U1/U2, Ctrl+0 OPC UA Studio, Ctrl+3 OPC UA tools, Ctrl+9 Workbench, Ctrl+S export report. Controls retain ordinary text editing behavior.

At high display scaling or on smaller screens, the window fits the monitor and the workspace offers horizontal/vertical scroll access. Side panels can also be resized in Preferences. Text keeps the selected display scaling and its embedded Inter font.

Select a supported process node and use Locate in 3D to highlight its inlet, distributor, rotor, water path/reservoir or electrical components. Open OPC UA in the scene inspector returns to the mapped node. Unknown/general nodes identify the whole unit. Actual flow controls arrow direction and travel; confirmed electrical power enables path highlighting. Missing endpoint quality grays unit materials and hides its flow overlays.
